# Source snapshots
Preserve raw source files unchanged. All implementations should read the same snapshots; cleaned and joined outputs are generated separately. [sources.csv](sources.csv) records input origins, selections, row counts, sizes and available acquisition metadata.

The initial snapshot is [raw/nyc-dogs-2024.csv](raw/nyc-dogs-2024.csv): 105,974 NYC dog-license records with `extract_year` equal to 2024, all eight published columns, and 11,139,556 bytes. It is a selected CSV export from the [NYC Dog Licensing Dataset](https://data.cityofnewyork.us/Health/NYC-Dog-Licensing-Dataset/nu7n-tubp). The explicit 200,000-row request limit exceeds the independently checked extract count; the saved CSV has the expected 105,974 rows, rather than a default-limited sample.

Each raw row represents a license period, not a guaranteed unique dog. The R pipeline handles names, missingness, ZIP representation and estimated-dog grouping in separate derived files. The original source remains unchanged.

The [SSA national baby-name source](https://www.ssa.gov/oact/babynames/limits.html) is saved as the unmodified annual text files in [raw/ssa/](raw/ssa/), alongside SSA's NationalReadMe.pdf. These 146 annual files cover 1880–2025 and contain 2,181,032 name/sex/year records. Together with the readme they occupy 28,255,978 bytes. The underlying tabulation dates to March 1, 2026.

The files were extracted byte for byte from the official national archive downloaded on November 5, 2026. That acquisition was 7,860,026 bytes with SHA-256 cd78e975ed7bb358e018dd62fbe14ced89295e9581c49172ca4eedcb011b3724. The source inventory describes the extracted directory and leaves its checksum field empty. Git retains the earlier archive version in history.

The baby-name notebook reads the 140 annual files for 1880–2019 directly. All rankings and overall name recognition use those 14 complete decades.

The character vector `missing_name_labels` beside the import in [dog-names.qmd](../dog-names.qmd#read-the-license-records) contains the six agreed labels: `UNKNOWN`, `NAME NOT PROVIDED`, `NONE`, `NA`, `.`, and `NONAME`. The import reads all six as missing values. Report one combined missing-name count overall and by recorded ZIP, then exclude those licenses before formatting names and dates or adding report fields. `BABY` remains a name; the source CSV retains the original labels.

Keep ZIP strings as recorded. All selected NYC dogs already have five-digit ZIPs. The 40 named licenses with short ZIPs fall outside the selected comparison, so preparation does not pad them with zeros.

Count and exclude named licenses whose recorded birth year is not a four-digit year from 1990–2024 before formatting or grouping. This removes 45 licenses, which form 42 distinct five-field keys in the independent check, and leaves 92,921 estimated dogs representing 100,119 named licenses. The [excluded-license report](derived/excluded_birth_year_licenses.csv) preserves the 45 recorded rows under short column names. The audit retains all 105,974 source rows; missing names and unusable years have their source row and reason but no dog IDs because they do not enter grouping.

The optional [birth-year inference reference](../birth-year-inferences.qmd) preserves the six considered replacements, their rationale and the original lookup operation. [birth_year_corrections.csv](lookups/birth_year_corrections.csv) is used only by that reference. It does not affect the main preparation. The greatest change in a plotted income-group share from excluding those six cases rather than keeping the inferences is about 0.007 percentage points.
## Geography and income inputs
[nyc-zcta-list.csv](raw/nyc-zcta-list.csv) is the unmodified CSV response for the `zcta5` column of [NYC Open Data's ZIP Code Tabulation Areas](https://data.cityofnewyork.us/City-Government/ZIP-Code-Tabulation-Areas/35j5-n34v), retrieved November 9, 2026. It contains 221 area codes and occupies 1,776 bytes. Use the published list as the study boundary, accepting that some listed areas extend outside NYC. Owner ZIPs do not establish precise residence within those areas.

[zip_zcta_income_ny_acs2024.csv](lookups/zip_zcta_income_ny_acs2024.csv) is a saved handoff reproduced from [Shweta's income script at PR #9 head `eb7ecc0`](https://github.com/Barkonomics-DataWrangling/barkonomics-pet-names/blob/eb7ecc0cbe336740d872d340aae8f95f760f57e3/R/income_zcta.R). It contains 2,150 New York ZIPs and occupies 208,948 bytes. The November 9 reproduction used the official HRSA 2024 crosswalk and ACS 2024 B19013 downloads saved during the November 5 review; its output matched the earlier run byte for byte. Regenerate with that script's `2024 NY` arguments, then copy its `data/processed/zip_zcta_income_ny_acs2024.csv` output to the lookup path. The analysis reads this saved handoff directly and requires no downloads or Census API access.

The income comparison keeps 92,541 dogs representing 99,719 licenses. It includes 364 dogs in areas reported as $250,000+; their exact numeric income is empty in the analysis table and `income_status = top_coded` preserves the known range. The 380 excluded dogs are reported separately: 275 map to areas outside the city list, 88 have no ZIP match in the NY lookup, and 17 map to city-listed areas without income. The earlier inspection found that the 88 unmatched ZIP cases comprise 72 outside New York State and 16 absent from the national crosswalk. Both counting-unit comparisons use the same selected dogs. The selected bands are under $50,000, $50,000–99,999, $100,000–149,999 and $150,000+. Their dog/neighborhood counts are 9,411/24, 41,341/94, 25,232/46 and 16,557/26, respectively. Each estimated dog receives equal weight within its band. The name-matching summary reports counts and shares for overall SSA recognition and each of the 14 decades, using all selected dogs in the band as the denominator. A dog can contribute to several decade numerators. The separate license-counted summary remains a check on the effect of repeat licenses.
## Generate and check the handoff
Open the repository as the editor workspace and run each notebook’s R chunks from top to bottom. Run dog preparation and baby-name preparation before analysis, then run the separate checks. The checks notebook verifies the saved tables during development; the birth-year notebook is an optional reference outside that sequence. Only analysis.qmd is an HTML deliverable. The [Quarto project file](../_quarto.yml) selects it as the sole project render target; run preparation, checks and the reference as code chunks without rendering separate documents.

```sh
quarto render analysis.qmd
```

- [Dog preparation](../dog-names.qmd) writes dogs_prepared_2024.csv, the source-to-dog mapping, missing-name summaries, excluded birth-year licenses and the cleaning report.
- [Baby-name preparation](../baby-names.qmd) writes the name reference, decade table, and cutoff counts.
- [Analysis](../analysis.qmd) writes the full dog/name handoff, the selected NYC income table with its income bands, group sizes, exclusions and their counts, the overall dog/license counting comparison, and the name-matching counts and shares by income group with each dog counted once. It also saves the [decade comparison](../figures/baby-name-decades-by-income.png) and [overall recognition](../figures/baby-name-recognition-by-income.png) charts as PNGs for review without HTML. The follow-up tables contain name counts and ranks within income groups, individual names’ contributions to the highest-minus-lowest decade differences, and matching shares within each neighborhood.
- [Birth-year inference reference](../birth-year-inferences.qmd) displays six considered corrections and their original join operation without writing prepared outputs. It is optional and not part of the preparation sequence.
- [Checks](../dog-names-checks.qmd) independently reads the sources and outputs to check the saved result.

The notebooks need Quarto and the R packages tidyverse, knitr and rmarkdown. Their shared table preview function lives in [helpers.R](../helpers.R). The [data dictionary](dog-name-data-dictionary.md) defines the output fields. Aslan used Codex for assistance with implementation and checks.

Keep the generated CSVs with this contribution for review and offline use. Regenerate the checks after changing a processing result. The [spike](../docs/active-spikes/dog-baby-name-data.md) records decisions and work history.
