## Runner credential and owner handoff
The organization-owned [Barkonomics Project Lifecycle App](https://github.com/organizations/Barkonomics-DataWrangling/settings/apps/barkonomics-project-lifecycle) is installed only for this repository. It has organization Projects read/write, repository Issues read-only and the required metadata read access. Organization Projects permission covers the organization’s projects; this workflow targets only the configured board. It has no webhook or user-authorization flow. The ordinary checkout/agent route continues using each contributor’s own GitHub account.

The App authenticates the shared GitHub Actions runner; its private key is not a collaborator setup dependency. The owner controls App creation/installation approval, key generation, Bitwarden storage and secret entry. The agent can prepare unsubmitted forms and configure the nonsecret client ID, but does not read, copy or enter the private key.

For key setup or a later owner-authorized rotation, use App settings → Credentials → Key pairs → New key. GitHub downloads a PEM file; the short SHA fingerprint on the page is not the private key. Save the entire PEM in the owner’s secure store, then enter its complete contents, including the BEGIN/END lines, directly as repository Actions secret `PW_APP_PRIVATE_KEY`. Do not create an OAuth client secret for this workflow. Set `PW_APP_CLIENT_ID` to the inspected App client ID and `PW_AUTH_METHOD=app`; these are nonsecret variables. The owner reported completing key storage and repository secret entry; the secret name and installation scope are verified without retrieving its value. Hosted preview and issue-event tests verify that the credential works for schema/issue reads and intended board writes. Contributors use the shared runner without configuring or receiving its key.
